# EousGate 产品与技术设计

## 1. 产品目标

EousGate 是 Windows 11 优先的独立桌面工具。它把 Windows 的“打开方式”选择变成一个可拖拽的边缘面板：用户拖动一个或多个文件靠近主屏幕边缘，选择面板中的软件并松开，即可使用该软件打开全部文件。

### 成功标准

- 从开始拖动到选定软件的路径短，用户不需要先打开 EousGate 的主窗口。
- 面板只在需要时出现，不遮挡正常工作区。
- 取消操作不会误打开软件；错误会给出可理解的反馈。
- 在浅色/深色模式和系统缩放下，图标、文字和点击区域保持可用。

## 2. 首版范围

### 包含

- 单屏：只保证主屏幕左边缘。
- 单文件与多文件：一次拖拽会话接受一个或多个普通文件。
- 混合文件类型只展示全部类型共同可用的软件，打开动作只启动一次。
- 通过 Windows 已有的文件关联和“打开方式”信息发现软件。
- 默认显示前 4 个软件选项，可展开查看更多。
- 松开鼠标后立即执行打开动作，不增加确认框。
- `Esc` 或移出左边缘取消并收起面板。
- 软件运行期间显示系统托盘图标，提供暂停/恢复、设置和退出。
- 跟随系统浅色/深色主题与显示缩放。
- 完全本地运行，首版不联网、不上传诊断数据。

### 不包含

- 多显示器布局。
- 文件夹拖拽。
- 收藏、排序、隐藏软件等完整自定义。
- 自动开机启动。
- Windows 10 的首版兼容承诺。
- 对可执行文件或脚本的额外拦截；遵循 Windows 原有行为。

## 3. 用户流程

1. 用户启动 EousGate；程序在系统托盘等待，不显示主窗口。
2. 用户从资源管理器拖动一个或多个文件，靠近主屏幕边缘。
3. 发生边缘唤出，打开面板从左侧以短暂动效出现。
4. 面板显示软件选项；鼠标悬停时突出当前选项并显示完整名称。
5. 用户把文件集合拖到软件选项并松开，所选软件接收全部文件，随后面板收起。
6. 用户按 `Esc`、把文件拖离边缘或在面板外松开，则拖拽会话以取消结束，不启动软件。

### 异常流程

- 没有候选软件：显示“未找到可打开的软件”，提供进入 Windows 系统“打开方式”的入口。
- 候选软件路径失效、启动失败或权限不足：显示失败原因，保留打开面板，允许用户重试或取消。
- 多文件没有共同软件：显示明确空状态，不进入仅支持单文件的系统选择器。
- 拖入文件夹或文件与文件夹混合：整批拒绝，不执行打开动作。

## 4. 界面设计

- 视觉参考 Windows 11 Snap Layouts 的贴边出现、分区和悬浮感，但不复制其品牌细节。
- 打开面板是无边框的紧凑浮层，软件选项使用稳定尺寸的图标 tile，名称在图标下方或旁侧显示。
- 默认展示 4 个选项；“更多”是面板内的明确操作，展开后仍保持滚动区域边界。
- 不使用长期固定的左侧栏，不在未拖拽时占用工作区。
- 面板和文本必须适配系统缩放，避免在 125%/150% 等比例下截断或重叠。
- 主题颜色、前景色和系统高对比度行为遵循 WPF/Windows 系统设置；不引入网络图片或远程字体。

## 5. 模块边界与接口

以下接口是行为契约，具体 Windows API 只能出现在适配层。

```text
IEdgeOverlayController
  - BeginSession(filePaths)
  - ShowCandidates(candidates)
  - CancelSession(reason)
  - CompleteSession()

IAppDiscovery
  - GetCandidates(filePaths) -> IReadOnlyList<AppCandidate>

AppCandidate
  - Id
  - DisplayName
  - ExecutablePath or ShellCommand
  - IconSource
  - IsAvailable

IOpenFileService
  - Open(filePaths, candidate) -> OpenResult

ISettingsStore
  - Load() -> UserSettings
  - Save(settings)

DragSession
  - FilePaths
  - PrimaryFilePath
  - FileCount
  - State: Detecting | PanelShown | Opening | Cancelled | Failed | Completed
  - SelectedCandidate
  - FailureReason
```

### 适配规则

- `IAppDiscovery` 通过 Windows Shell/文件关联能力收集候选软件，并过滤明显失效的路径。
- `IAppDiscovery` 对混合类型按候选 ID 和兼容启动参数求交集，并保留首个文件类型的候选顺序。
- `IOpenFileService` 使用选定软件的 Shell 命令和全部文件参数执行一次打开动作，不修改系统默认关联。
- 任何注册表读取、Shell 调用和进程启动错误都转换为领域层可显示的错误信息。
- `ISettingsStore` 只保存本机用户设置，例如暂停状态和默认显示数量；不保存文件内容。

## 6. 运行与发布

- 技术路线：C#/.NET + WPF。
- 目标平台：Windows 11 x64；其他架构另行评估。
- 发布形式：绿色免安装包。
- 不自动注册开机启动项；用户手动启动后，在本次运行期间保持托盘常驻。
- 托盘菜单至少包含：暂停/恢复边缘唤出、设置、退出。
- 暂停状态应立即阻止新拖拽会话，但不强制终止已经打开的面板。
- 首版无网络依赖；日志仅保存在本机，避免写入文件路径和内容，除非为排错所必需。

## 7. 测试验收矩阵

| 场景 | 预期结果 |
| --- | --- |
| 启动程序 | 托盘图标出现，桌面无遮挡 |
| 单个常见文件拖到主屏左边缘 | 打开面板出现 |
| 多个同类型文件拖到接收条 | 显示该类型软件，选择后只启动一次并接收全部文件 |
| 混合类型文件拖到接收条 | 仅显示共同软件；没有共同软件时显示空状态 |
| 候选软件超过 4 个 | 默认显示 4 个，可展开更多 |
| 拖到软件选项并松开 | 选定软件打开该文件，面板收起 |
| 按 `Esc` 或离开边缘 | 会话取消，不启动软件 |
| 没有候选软件 | 显示明确提示和系统入口 |
| 软件路径失效/权限不足 | 显示原因，面板保留，可重试 |
| `.exe`/脚本文件 | 遵循 Windows 原有打开方式 |
| 浅色/深色和 100%/125%/150% 缩放 | 无重叠、无截断、点击区域稳定 |
| 暂停功能 | 新会话不唤出面板，恢复后正常 |
| 网络监控 | 程序启动和使用期间无网络请求 |
| 多屏、文件夹 | 文档标记为不支持，不产生未定义的打开动作 |

## 8. 后续演进候选

多显示器边缘唤出、文件夹语义、收藏与排序、Windows 10 兼容、自动更新和可选的开机启动，应在独立需求中重新评估，不预先塞入当前接口行为。

# v0.2.0-beta.11 · 真实复制计数核验

此前 beta.10 的剪贴板集成使用合成消息和读取器，只证明通知到达后的逻辑，不能证明微信或 Edge 的复制操作必然产生通知。本轮明确修正这一验证边界。

真实 WPF 文本框连续执行四次 Copy 时，旧监听器曾交付五次回调，其中前两次序列号相同。Windows 延迟呈现可能再次通知；新版在仍持有剪贴板锁时取得读取完成后的序列号，每个非零序列只交付一次。内容相同但序列不同的下一次复制仍计数，监听重启清空缓存；不以 Ctrl+C 盲目累加旧剪贴板内容。

真实链路复测：四次 Copy 对应四次回调；默认阈值三次时只提交一轮、两个不同网址的打开请求，第四次不重开。浏览器启动由替身接收，未实际访问这些网址。可选 `--clipboard-real-smoke` 会短暂使用真实剪贴板，仅在原内容为纯文本时执行并恢复原文本；富内容直接跳过。默认完整测试仍使用不修改用户剪贴板的合成场景，并新增同序列去重与监听重启回归。

Edge 桌面测试因 Computer Use 无法可靠确认当前浏览器网址而被工具停止，未执行 Ctrl+C；微信也未实测，不能宣称本次已修复用户在这两款应用中的现象。当前读取到的实际助手保存配置尚无自动打开字段，按默认关闭解释；需在“通用设置 → 剪贴板链接”勾选“连续复制自动打开”、应用设置，并启动网页快开。HTML 原型中的勾选不会修改实际助手配置。

发布采用独立源码快照，排除另一对话尚未验收的文件快开改动，保留共享工作区原样。该包专注剪贴板通知计数修正；验证明细见当日日志。

Windows 行为依据：[Clipboard sequence number](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber)、[Using the Clipboard](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard)。

# EousAssistant v0.2.0-beta.1

日期：2026-10-16。整合三个内置模块为单进程、单托盘助手。外部软件本次仅预留接口。

## 已完成验证

- Release 构建：0 警告、0 错误。
- 60/60 自动化测试：独立／四种批量操作、幂等及并发转换、失败隔离、选择持久化、旧设置复制迁移、历史合并与原文件保留、UNC 路径及原有文件／网页领域行为。
- 窗口样式 smoke：三侧接收条、打开面板、剪贴板提示、设置及所属编辑器的 HWND 样式。
- Assistant UI smoke：真实 XAML 四个批量按钮绑定、勾选与状态分离、浅深色 100%/125%/150% 离屏渲染、最小布局、三轮 FolderHop 原生窗口创建／释放。
- 真实宿主 smoke：隔离数据、关闭历史采样，两轮全部启动／停止，分别停止 FileHop 和 WebHop 不影响其他工具，所有 WPF 工具窗口释放、FolderHop 旧版互斥标记释放。没有发送桌面输入。
- 实际面板检查：首次零模块运行；FileHop、WebHop 启动成功；旧 FolderHop 存在时对应模块明确失败且其他工具不受影响。
- 剪贴板消息/UI 联调通过：原生消息加模拟文本读取器覆盖占用重试、重复复制、倒计时、监听启停、点击分派和设置保存。首次被真实鼠标悬停干扰，改用内部交互探针固定无悬停后通过；生产逻辑仍读取真实鼠标／键盘焦点，不操纵用户鼠标。
- 一次隔离测试宿主观测：全部模块运行、文件夹采样暂停时，工作集约 134.3 MiB，2 秒平均整机 CPU 约 0.13%。宿主包含测试与 WPF 环境，此数据不是完整产品基准，也不构成与独立软件的同条件比较。

## 当前限制与待复测

- 用户按物理 Escape 停止了 Computer Use，本轮停止后未继续桌面输入。用户之后已退出旧版 FolderHop，三个模块的实际宿主启停已在无输入测试中通过。
- 尚未在 Edge 当前页面验证完整按钮点击、中文目录跳转及原文件名保留，也未在新宿主中复跑跨进程打开／保存导航。原生导航沿用 FolderHop 0.1.1 已验证逻辑，新增导航计时器释放；这不能代替新版桌面验收。
- 离屏渲染覆盖缩放输出，不代表已经切换实际监视器 DPI。实际 100%/125%/150%、高对比度、完整鼠标拖拽及系统任务切换仍需桌面检查。
- 未在干净 Windows 虚拟机测试。程序未签名。

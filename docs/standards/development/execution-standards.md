# 开发执行标准

## 小步推进

- 一次只推进一个阶段和一个主要行为。
- 先写目标和验收条件，再改代码；不把无关重构混入当前任务。
- 当前阶段未通过验收，不开始下一阶段。

## 记录与审查

- 每次任务开始、过程中和结束都更新 `docs/dev-status/`。
- 完成项必须附验证命令或手工场景；阻塞项必须写出原因和下一步。
- 需求变化更新需求标准；架构变化新增或更新 ADR。
- 修改前后检查工作树，保留用户已有改动。

## 安全边界

- 不修改、提交或手工清理 `bin/`、`obj/`、`.tmp-*` 等生成物，除非任务明确要求。
- 不引入未经记录的外部依赖、网络调用、自动启动项或系统默认关联修改。
- 任何不可逆操作先确认精确目标并保留可恢复路径。

# MARGIN 透明材质与美术风格研究

研究日期：2026-11-08。用户指定参考：[jiuyang5354/bilibili-margin](https://github.com/jiuyang5354/bilibili-margin)。

研究基于提交 `0e4daf046f38dc37752ebbad3ac40702eb37b894` 的源码，以及仓库提供的浅色首页、深色首页和收藏夹截图。截图可能早于此提交；未安装扩展，未实测动态折射、帧率及浏览器兼容性。

用户明确喜欢该项目的美术风格，尤其是透明风格。本文作为后续设计参考，不替代 EousAssistant 已确认的视觉规范。

## 视觉判断

整体可以概括为：编辑式排版、暖白或墨黑底色、柔和环境色、局部玻璃控件，以及有实体厚度的交互细节。

首页截图中，蓝色环境光连续穿过画布与足迹面板，建立空间联系；视频内容直接排在画布上，玻璃集中在足迹面板和顶部控件。收藏夹截图中，前袋模糊地映出后方封面的颜色，下半部逐渐变实，承托文件夹名称。透明材质有疏密变化，因此主内容依然突出。

核心配方：**背景色透入 + 局部模糊 + 表面染色 + 方向性亮边 + 柔和投影 + 清晰前景**。液态效果在此基础上增加边缘折射。

## 三种材质分别学习

| 材质 | 实现证据 | 值得借鉴的视觉作用 |
| --- | --- | --- |
| 磨砂玻璃 | 半透明底色、背景模糊与饱和度调整；菜单示例为 24px 模糊、1.6 倍饱和度 | 保留背景色，抑制背后的细节，承托文字 |
| 液态玻璃 | `liquid-glass.ts` 按控件尺寸生成位移图，使用圆角矩形边缘法线和折射曲线；默认折射率计算值为 1.5 | 边缘压缩背景，表现弧面与厚度；中部保留较平静的阅读区域 |
| 立体玻璃文件夹 | 前后板、封面、纸张、模糊副本、染色、高光和投影分层组合 | 让用户感到内容被装在半透明口袋中，而非贴在一张平面卡片上 |

文件夹前袋使用的是内容副本的 `filter: blur(22px) saturate(1.5)`，并非全部依赖实时背景模糊。其浅色染色层由顶部约 16% 不透明白色，经过中部约 50%，增加到底部约 93%；深色使用墨色渐变，底部约 94%。这些数字是该组件的具体取值，不是全站统一参数。

## 透明风格的关键细节

1. **背景提供环境色。** 大面积色彩变化经过玻璃后仍然可见。底色过实会遮住这种联系，背景过于琐碎又会干扰阅读。
2. **用边缘交代厚度。** 吸顶胶囊叠加不同方向的内高光、内暗部与外投影；亮度不沿四边机械地保持一致。
3. **文字独立于材质。** 透明度施加给底色或材质层，正文和图标保持明确的前景色。整块容器统一降低 opacity 不适合作为基础实现。
4. **透明度服从内容。** 命令面板基础样式使用 86% 表面色，文件夹菜单使用 72% 底色；承载不同信息的容器采用不同厚度。
5. **深浅主题分别调材质。** 浅色画布为 `#f5f4f1`，深色为 `#111112`；前者呈乳白透光，后者呈烟灰染色，阴影、边线和高光也分别调整。
6. **排版提供秩序。** 衬线字体承担部分标题，无衬线承担正文和控件，等宽字体承担时间与数字；4px 间距网格和较充分的留白让玻璃有展示空间。

## 必须注意的当前实现

- `03-cards.css` 给抽屉定义了 90% 表面色和 28px 背景模糊，但后续 `08-home-search.css` 明确将播放页抽屉与收藏夹抽屉改为实色并关闭背景模糊。不能把前面的基础声明当成所有抽屉的最终效果。
- `attachGlass` 默认液态模式使用 6px 模糊、150% 饱和度和位移滤镜；普通柔和模式通常使用 16px 模糊、110% 饱和度。模糊强弱与折射强弱是不同参数。
- 位移图按尺寸缓存，尺寸变化稳定后再生成；代码还提供减少透明度、平面材质和减少动画的处理。
- 常规动效规范采用约 150ms 悬停、200ms 小位移、300ms 面板、400ms 大块进出；玻璃文件夹的组装演出另有更长时序。

## 对 EousAssistant 的借鉴建议

以下是研究推导的设计建议，尚未实现或验证：

- 保留暖白、鼠尾草绿、橙色操作和 Eous 原画的现有识别，在打开面板、链接提示、少量悬浮控件上优先试验玻璃材质。
- 主工具清单继续保持清晰的文字与状态层次；设置抽屉采用较厚的磨砂面或稳定实色承托密集内容。
- 若引入环境色，优先从现有鼠尾草绿和角色配色中提取少量柔和色彩，避免全界面同时使用强烈的渐变、亮边和折射。
- 分开控制底色不透明度、模糊、边缘亮度、投影与折射，不用单一“透明度”参数代替整个材质。
- 原生 Windows 版本需要另外验证背景采样与合成方式。网页 CSS/SVG 的参数不能直接视为 WPF 的可用实现；尤其不能把模糊整个控件当作背景磨砂，以免文字也变糊。
- 评审时重点看：浅色/深色背景上的文字、复杂桌面下的辨识度、相邻材质层是否过厚、拖拽反馈是否及时，以及关闭透明和动效后的可用性。

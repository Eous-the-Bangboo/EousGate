# EousAssistant：从零梳理界面方向

日期：2026-10-20
阶段：产品任务与信息架构已梳理；三个文字方向待选择。

## 任务边界

用户要求：运用 oil-ui，不参考当前已有 UI 设计，从头梳理界面。

本轮以领域能力和使用行为为输入，不以已有配色、布局、组件、截图或历史方向为输入。阅读产品说明时遇到的历史视觉描述不作为设计依据；未打开 Presentation、旧设计目录和项目截图。没有修改产品源码或重新发布程序。

## 产品与用户任务

品类：Windows 11 本地桌面效率工具管理器。用户需要在文件、链接、目录之间快速流转，并按需管理辅助程序。它通常短暂打开后回到托盘，不需要持续占据桌面。

设计北极星：打开就知道哪些工具在工作，并能在对应工具旁完成下一步。

优先级：
1. 确认真实运行状态，启动或停止某个工具。
2. 找到对应工具的配置，调整后明确应用结果。
3. 添加和管理外部程序，修复路径或解释启停失败。
4. 通过临时浮层选择软件、打开链接或跳转目录。

设备假设：Windows 11 桌面、鼠标键盘，首轮以 100% 缩放设计，选定方向后验证 150% / 200% 和小工作区。窗口尺寸是候选设计尺寸，不是已验收尺寸。

## 重新组织信息架构

### 第一层：工具总览

首屏完整显示三个原生工具和 Ditto、Everything、无线麦 Sayall；自定义程序可继续滚动。
- 原生组、外部组保留产品定义的分组名称。
- 每项只保留图标、中文名、一句用途、真实状态、启停操作和设置入口。
- 全部启动、全部关闭放在列表操作区；添加程序归属外部组。
- 不把开关请求位置当作实际运行结果。启动中、停止中、失败都有文字反馈。
- 失败在对应行显示原因与重试或修复入口，其他工具保持可操作。
- 无统计大卡片、欢迎语、大幅宣传标题和重复的“本地安全”口号。

### 第二层：工具详情与通用设置

文件快开：触发边缘、候选软件、文件类型及推荐。分类与后缀选择按需展开；当前后缀和未应用草稿始终明确。
网页快开：链接提示位置和时长；连续复制自动打开默认关闭，次数作为从属选项。
文件夹快跳：目录记录、辅助按钮、历史与收藏管理、导入旧数据。
外部程序：可执行文件路径、参数、运行状态、允许超时强制结束的选择。运行中编辑限制沿用领域规则。
通用设置：应用级外观、诊断等；不再承载单个工具的行为配置。

配置页统一采用“标题与状态 → 分组设置 → 应用/取消”的阅读顺序。保存中显示进展并防止重复提交；失败保留输入；有草稿时离开需明确处理。

### 第三层：临时操作界面

打开面板：文件拖到边缘后出现，软件选项是主角，默认前四项；无候选时显示系统打开方式入口。
链接提示：链接标题或可辨识地址是主角，支持逐项打开、关闭和倒计时暂停；失败地址可重试。
目录选择：搜索、最近访问、收藏、当前打开；目录名称与路径有清楚层级。

三类浮层沿用选定方向的字体、间距和状态语法；功能边界和数据用途不随视觉重设计改变。

## 标杆与取舍

参考仅用于比较同类产品的操作基线，不作为 EousAssistant 的品牌模板。官方文档图片可能与其最新安装版存在差异。

来源：
- PowerToys Run 插件管理：https://learn.microsoft.com/en-us/windows/powertoys/run
- PowerToys 官方原图：https://learn.microsoft.com/en-us/windows/powertoys/images/run/plugin-manager.png
- Raycast 设置：https://manual.raycast.com/settings

已实际查看并保存：
- references/powertoys-plugin-manager.png
- references/raycast-launcher.png

从两张图观察到的八条关系：
1. PowerToys 的图标、名称、说明集中于行左侧，开关固定在右侧；控制同一对象的视线路径稳定。沿用对象与动作相邻。
2. PowerToys 同时显示 On 文字与蓝色开关；颜色之外也有状态提示。EousAssistant 需进一步区分请求与真实运行确认。
3. PowerToys 使用细边框、浅底和相近行高；重复对象容易扫描。沿用对齐纪律，候选不必都使用独立卡片。
4. PowerToys Windows Search 在所属行下方展开设置；配置与对象之间关系清楚。EousAssistant 的复杂文件类型配置改用详情区，避免撑长首页。
5. PowerToys 顶部警告带占据明显高度；适合全局冲突。EousAssistant 的单项错误放在工具附近，只在确有全局影响时使用全局提示。
6. Raycast 左侧以选中底色标出当前 Launcher，右侧承载对应内容；导航和配置职责清楚。保留稳定当前位置反馈，短工具列表不必照搬长导航。
7. Raycast 设置组内部采用横线分隔，字段左、值右；平面关系比层层套卡更直接。详情页面可采用同类排布。
8. Raycast 用较小灰字解释次要设置，说明较长时提供 Show more；有助于主标签先被读到。EousAssistant 保留影响决策的信息，其余按需展开，不依靠大量小字塞入首屏。

未从静态图推断动效、实际点击反馈、精确字体或真实尺寸。

品类默认色彩常见为中性底加蓝色开关。PowerToys 参考为浅灰蓝底和蓝色控件；Raycast 参考为深灰底和蓝色开关。以下方向分别使用朱红、钴蓝与黑白字色体系；方向差异同时体现在骨架、字体和主视觉，不能只按明暗区分。

共同调性：安静、精致、中等密度、轻分量、偏严肃。依据是短时打开、重复启停和配置任务，需要准确识别对象及状态；不需要角色大图持续占据操作区。

## A：工具清单（推荐）

北极星：像检查一张工具清单，所有状态和操作一次看清。
生成引擎：桌面工具管理的登记清单；以稳定列对齐体现可控性。
首屏骨架：980 × 700 候选窗口；左侧约 160px 导航，右侧一行标题与批量操作，下方两个分组共六行，完整呈现六个工具。详情在选择设置后于右侧展开，首页不永久留空详情栏。
阅读顺序：工具名 → 真实状态 → 启停；设置入口固定在同一列。
字体：Segoe UI Variable，中文回退 Microsoft YaHei UI；页名 24/600，工具名 16/600，正文 14，状态 13；字体可用性后续核实。
色彩：底 #F5F6F7、内容 #FFFFFF、字 #222529；主动作朱红 #B54135、选中底 #F9E9E5、边框 #D9DEE3、禁用 #747C86。朱红只强调当前操作和选中位置，运行状态另配文字，不让红色承担成功含义。
主视觉：六行对齐的工具及实际应用图标；不用装饰插画。
控件：6px 圆角、1px 边框，低对比行分隔；动作文字优先，图标作为辅助。内置工具用 Segoe Fluent Icons，外部程序用真实应用图标。
辨识点：状态列和动作列稳定排列，详情展开时仍能认出所配置的工具。
放弃：三张大功能卡、统计面板、长篇功能介绍。
优势：六个起始工具与未来自定义程序都能承载，状态比较和批量操作直接。
代价：情绪表现较弱，需要靠排版、行距和操作反馈完成品质。

## B：三路操作台

北极星：文件、链接、目录三条通道各自清楚，按需接通。
生成引擎：三种真实输入动作形成三条水平通道；只借用通道组织，不仿造硬件面板。
首屏骨架：1000 × 720 候选窗口；无左侧导航，一行顶栏；上部三条约 90px 的横向原生工具带，下部为外部程序紧凑列表。六个初始工具均在首屏。设置在原生工具带所属位置展开后形成单工具配置页，顶部保留返回位置。
阅读顺序：文件/链接/目录 → 当前状态 → 该通道操作；外部程序作为独立次级区域。
字体：Bahnschrift 用于拉丁编号及页名，中文 DengXian 回退 Microsoft YaHei UI；通道名 22/600、正文 14、编号 34；中文字体可用性后续核实。
色彩：钴蓝结构面 #183AC7、浅蓝白内容 #F2F5FF、白色标题 #FFFFFF；强调 #FFD66A、选中底 #DCE6FF、边框 #C7D1ED、禁用 #68758C。钴蓝只占三路通道的组织面，正文保持高对比。
主视觉：三条完整横向带及文件、链、目录三个领域符号；蓝色面积形成识别，不依赖大图。
控件：4px 圆角、平直分隔线；通道带右端固定动作，启动过程中在对应通道内部显示进展。
辨识点：明确的三路结构，从产品的三种输入行为推导。
放弃：常驻侧栏、卡片网格、逐项相同的大块容器。
优势：原生三工具关系突出，品牌识别较强。
代价：原生与外部视觉权重不同；要防止外部管理入口被压低。蓝色与 PowerToys 同属蓝色系，需用通道骨架和色块面积区分，不复制其浅蓝卡片。

## C：紧凑命令面板

北极星：唤出、找到工具、完成一个动作，立即回到原工作。
生成引擎：托盘助手的短会话，用紧凑的对象列表承载动作。
首屏骨架：640 × 620 候选窗口；无侧栏；顶端一行标题及设置入口，下面一个工具名筛选框；两个分组共六行，底部固定当前选中工具的动作区及清楚分离的全部操作入口。未输入时显示完整初始列表，不以搜索阻挡发现。
阅读顺序：工具名与状态 → 选中工具 → 底部主动作。行尾仍可直接启停，键盘选择与鼠标按钮共享状态。
字体：Microsoft YaHei UI 正文，Consolas 用于键位与状态编号；工具名 15/600、正文 14、页名 19、键位 12。
色彩：底 #F3F3F0、内容 #FFFFFF、主动作 #202221、选中底 #E4E6E1、边框 #CFD3CD、禁用 #767B74；以黑白字重形成身份，颜色交给真实应用图标，状态同时用文字和形状识别。
主视觉：聚焦行的反白块与底部动作文字；不使用装饰性主视觉。
控件：2px 圆角，1px 分隔线；焦点轮廓明确；工具筛选只匹配已有工具名，键盘快捷方式的具体映射待方向确认。
辨识点：明显更小的窗口和固定动作落点，贴合托盘短时操作。
放弃：长驻导航、功能卡、首页展示完整设置。
优势：占用桌面最少，高频使用快。
代价：增加工具名筛选及键盘导航的展示层工作；复杂设置需要进入独立详情页，初次发现性弱于 A。筛选是提议中的界面能力，当前未实现。

## 方向差异检验

| 维度 | A | B | C |
| --- | --- | --- | --- |
| 骨架 | 左导航 + 完整清单 + 按需详情 | 顶导航 + 三路横带 + 外部列表 | 紧凑单列 + 固定动作区 |
| 字体关系 | 系统无衬线，列对齐 | 较大通道名 + 工业编号 | 小尺度中文 + 等宽键位 |
| 色彩身份 | 白灰 + 少量朱红 | 钴蓝结构面 + 淡金主动作 | 黑白灰，色彩交给应用图标 |
| 主视觉 | 对齐的状态与动作列 | 三条完整通道带 | 反白选中行与底部动作 |

四项没有同时复用；B 在结构和色块上作明确选择，C 打破固定侧栏与卡片网格。各方向仍须在实际首屏渲染后做差异复核，文字差异不能代替画面验证。
